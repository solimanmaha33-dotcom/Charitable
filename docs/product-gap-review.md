# مراجعة النواقص — مرام الخير

## اللي اتضاف في التحديث ده

- وضع ليلي أو نهاري، يبدأ حسب إعداد الجهاز ويحفظ آخر اختيار على نفس المتصفح.
- ملخص للرئيسية فيه أعداد الأسر والحالات والتبرعات. كل عدد يظهر فقط للموظف المسموح له بقراءة سجله، ولو تعذّر تحميله تظهر رسالة بدل الصفر.
- أمثلة أسئلة للمساعد، وتنبيه إن الإجابات قد تكون ناقصة ويجب مراجعة ملف الحالة قبل الاعتماد عليها.
- توضيح أن المساعد الحالي يستخدم Cloudflare Workers AI من ربط الخادم، ولا يحتاج مفتاح API.

## نواقص مهمة ما زالت تحتاج قراراً

- **متابعة الحالة:** مفيش حالة عمل مثل «جديدة / تحت المراجعة / تم التواصل»، ولا موعد متابعة أو موظف مسؤول. إضافتها تحتاج تحديد خطوات العمل والحقول المطلوبة قبل تعديل قاعدة البيانات.
- **تصحيح استلام الكفالة:** بعد تسجيل الاستلام، النظام يمنع تغيير التاريخ أو المبلغ لحماية السجل. لسه مفيش طريقة تصحيح بموافقة مدير وسجل واضح للتعديل.
- **سجل النشاط:** يوجد سجل إداري محدود لإنشاء الموظفين وتغيير صلاحياتهم، لكن مفيش شاشة تعرض من فتح أو عدّل ملفات الأسر والحالات.
- **النسخ الاحتياطي:** دليل التشغيل يشرح نسخ قاعدة البيانات والملفات واستعادتها، لكن مفيش مهمة نسخ تلقائي مؤكدة داخل المشروع. يلزم إعدادها ومراجعة الخطة والتكلفة لدى Supabase.
- **تصدير وطباعة:** مفيش تقارير قابلة للطباعة أو تصدير قوائم الأسر والتبرعات؛ يلزم تحديد من يقدر ينزّل بيانات حساسة وبأي صيغة.
- **مزود المساعد:** الكود مربوط حالياً بـCloudflare Workers AI فقط. مفاتيح OpenAI أو Gemini أو OpenRouter لن تعمل بمجرد إضافتها إلى Cloudflare؛ يلزم تطوير وربط المزود في الخادم أولاً. Kilo Code يحتاج معرفة عنوان API وصيغة النموذج.

## توضيح إعداد مفاتيح الذكاء الاصطناعي

- **Cloudflare Workers AI الحالي:** يستخدم ربط `AI` في `wrangler.jsonc`؛ لا يحتاج مفتاح API إضافياً.
- **OpenAI أو Gemini أو OpenRouter لاحقاً:** بعد إضافة دعمها للكود، يوضع المفتاح كـSecret في إعدادات مشروع Cloudflare Pages، ضمن بيئة Production، ولا يوضع في GitHub أو في مفتاح يبدأ بـ`VITE_`.
- اشتراك ChatGPT أو Gemini للمستخدم لا يعني تلقائياً وجود رصيد API للموقع؛ خدمة API لها مفتاح وشروط استخدام وحساب تكلفة منفصل.

ما اتغيرتش قاعدة البيانات ولا صلاحيات الوصول في مراجعة النواقص دي. أي تطوير لحالات المتابعة أو تصحيح الدفعات أو سجل النشاط يحتاج تصميم منفصل واختبار ترحيل قاعدة البيانات قبل استخدامه مع بيانات حقيقية.
