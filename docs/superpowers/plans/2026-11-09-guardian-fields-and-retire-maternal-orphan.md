# إخفاء بيانات المسؤول وإيقاف تصنيف يتيم الأم — خطة التنفيذ

> **لمنفذ آلي:** اتبع المهام بالترتيب، واستخدم دورة اختبار أحمر/أخضر لكل تغيير.

**الهدف:** إخفاء قسم المسؤول عند اختيار أرملة أو هجر أو مطلقة، وإيقاف «يتيم الأم» كنوع جديد دون فقدان سجلاته القديمة.

**التصميم:** مصدر قائمة الأنواع هو `categories.ts`. النموذج يخفي قسم المسؤول بناء على الأنواع المختارة. ترحيل Supabase يمنع التصنيف المتقاعد في الإدخال الجديد ويبقيه محفوظاً عند تحديث الملف التاريخي، بينما تعدّل الأرقام لاستبعاده.

**التقنيات:** React وTypeScript وVitest وSupabase/PostgreSQL وpgTAP.

**المواصفات:** `docs/superpowers/specs/2026-11-09-guardian-fields-and-retire-maternal-orphan-design.md`

## القيود العامة

- لا تمسح سجلات الحالات القديمة ولا تغيّر أنواعها تلقائياً.
- الواجهة والمساعد وقاعدة البيانات لا تسمح بإنشاء حالات «يتيم الأم» جديدة.
- الأرقام والإحصاءات تعتبر «يتيم الأب» النوع المتبقي لتعريف الأيتام.

## نقاط المراجعة

- تغيير التصنيف مع وجود بيانات قديمة: يجب أن تبقى بيانات الملف كما هي.
- «يتيم الأم» في ملف محفوظ: يبقى قابلاً للعرض، ولا يدخل في الفلتر/الإحصاء الجديد.
- إخفاء قسم المسؤول أثناء إدخال بيانات ثم إزالة النوع: تظهر القيم المدخلة كما هي.
